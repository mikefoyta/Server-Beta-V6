OS Deployment, Scripting & Licensing

PXE, WDS/MDT, Kickstart, cloud-init, UEFI/GPT vs. Legacy BIOS/MBR, LVM, PowerShell/Bash/Ansible, and per-core/CAL licensing.

DOMAIN SCOPE (VLAN 12): Everything inside this room belongs strictly to Zero-Touch OS Deployment (PXE/WDS/Kickstart), Firmware & Partitioning (UEFI/GPT vs. BIOS/MBR), Logical Volume Management (LVM), Automation/Scripting, and Enterprise Licensing.

Automated Bare-Metal OS Deployment

  • PXE Boot (Preboot Execution Environment): NIC firmware requests an IP and boot server pointer via DHCP (Options 66 & 67), downloads a bootstrap loader over TFTP (UDP 69), and streams the OS installer over HTTP/SMB/NFS.
  • WDS & MDT (Windows): Windows Deployment Services + Microsoft Deployment Toolkit automate Windows Server imaging using Unattend.xml answer files.
  • Kickstart & Preseed (Linux): Declarative answer files automating partitioning, package selection, root passwords, and post-install scripts on RHEL/Rocky (Kickstart) or Debian/Ubuntu (Preseed).
  • cloud-init: Industry-standard cross-distro initialization agent configuring SSH keys, hostnames, network interfaces, and user data on first boot of cloud/VM templates.

Firmware Boot Modes & Disk Partitioning

  • UEFI vs. Legacy BIOS: UEFI uses a 64-bit pre-boot environment, supports drives > 2 TB, boots from an EFI System Partition (ESP), and enforces Secure Boot; Legacy BIOS is limited to 16-bit real mode and 2 TB boot disks.
  • GPT vs. MBR: GUID Partition Table (GPT) supports up to 128 primary partitions, drives up to 9.4 ZB, and stores redundant backup partition headers at the end of the disk; MBR supports max 4 primary partitions and 2 TB max volume size.
  • Linux LVM (Logical Volume Manager): Abstracts physical disks into PV (Physical Volumes) → VG (Volume Groups) → LV (Logical Volumes), allowing online filesystem resizing and spanning across multiple disks.

Server Scripting & Configuration Management

  • PowerShell (.ps1): Object-oriented Windows automation shell (Verb-Noun cmdlets like Get-Service, Restart-Computer); managed remotely via WinRM/PSRemoting.
  • Bash / Shell Scripting (.sh): Text-stream automation on Linux using #!/bin/bash shebang, exit codes ($?, where 0 = success), pipes (|), and environment variables.
  • Scheduled Tasks: Windows Task Scheduler and Linux cron (minute hour day month weekday command) or systemd timers for recurring maintenance jobs.
  • Configuration Management / IaC: Idempotent tools like Ansible (agentless over SSH/WinRM using YAML playbooks), Puppet, and Chef enforce desired server state and prevent configuration drift.

Enterprise Server Licensing Models

  • Per-Core Licensing: Standard Windows Server Datacenter/Standard model; requires licensing all physical cores in the server (minimum 8 cores per processor / 16 cores per server).
  • Per-Socket Licensing: Licenses each populated physical CPU socket on the motherboard regardless of core count (common in legacy hypervisor licensing).
  • CALs (Client Access Licenses): Required in addition to Windows Server OS licenses—licensed either Per-User (1 user, unlimited devices) or Per-Device (1 shared workstation, unlimited shift users).
  • Volume Activation (KMS vs. MAK): KMS (Key Management Service) activates enterprise servers locally on the LAN (must renew every 180 days); MAK (Multiple Activation Key) activates directly against Microsoft servers up to a fixed activation count.
