High Availability (HA), Fault Tolerance (FT) & Clustering

HA automated failover vs. FT synchronous lockstep, Active/Passive vs. Active/Active, quorum witnesses, and STONITH.

DOMAIN SCOPE (VLAN 04): Everything inside this room belongs strictly to High Availability (HA), Fault Tolerance (FT), Failover Clustering, and Load Balancing.
Architecture Downtime on Host Failure Execution Mechanism Resource & Network Overhead
High Availability (HA) Brief interruption (Seconds to minutes while workload restarts) Cluster detects failed node via missed heartbeats and automatically reboots/restarts VMs or services on a surviving node. Low overhead; active TCP sessions drop during failover and clients reconnect.
Fault Tolerance (FT) Zero downtime (0 ms interruption; zero dropped packets) Runs a live secondary shadow instance in continuous synchronous lockstep; instant transparent cutover if primary fails. High overhead (2× CPU/RAM consumption + dedicated ultra-low-latency logging link).

Cluster Topologies: Active/Passive vs. Active/Active

  • Active/Passive Cluster: Node A serves 100% of live traffic while Node B sits idle in standby mode waiting to take over; guarantees full uncontended performance upon failover.
  • Active/Active Cluster: Both Node A and Node B actively process live workloads simultaneously; maximizes hardware utilization, though surviving nodes must absorb extra load during failover.
  • Shared-Nothing vs. Shared-Storage: Shared-storage clusters require all nodes to access common backend storage; Shared-nothing clusters replicate local storage asynchronously/synchronously between nodes.
  • Rolling Upgrades: Draining workloads off Node A onto Node B to patch/reboot Node A without application downtime, then reversing the process.

Heartbeats, Quorum & Split-Brain Prevention

  • Heartbeat Network: Dedicated private NIC link between cluster nodes transmitting continuous "I am alive" keepalive pulses every second.
  • Split-Brain Condition: Occurs when the heartbeat link breaks while both nodes are still alive; each node assumes the other is dead and attempts to seize ownership of the same resources simultaneously, risking data corruption.
  • Quorum Majority Rule: A cluster partition must hold > 50% of total votes to remain online; minority partitions automatically shut down cluster services.
  • Quorum Witness (Disk or Cloud): Tie-breaker vote used in 2-node (even-numbered) clusters so one surviving node + witness = 2 of 3 votes (majority).
  • STONITH (Shoot The Other Node In The Head): Automated power-fencing mechanism that hard-powers off an unresponsive node so it cannot corrupt shared resources.

Load Balancing Mechanics & Health Checks

  • Round Robin / Weighted Round Robin: Distributes incoming client requests sequentially across pool servers (weighted sends more traffic to higher-capacity servers).
  • Least Connections: Routes new requests to the backend server currently handling the fewest active sessions.
  • Session Persistence (Sticky Sessions): Binds a user's session to a specific backend node via cookies or source IP hash so in-memory shopping carts/sessions aren't lost.
  • Layer 4 vs. Layer 7 Load Balancing: Layer 4 routes based on IP and TCP/UDP port (fast, packet-level); Layer 7 inspects HTTP headers, URLs, and cookies (content-aware routing + SSL offloading).
  • Active Health Probes: Load balancer periodically polls backend servers (HTTP GET, TCP handshake); failed nodes are automatically pulled out of rotation until healthy.
  • VIP (Virtual IP) / Floating IP: Single front-end IP address presented to clients that dynamically moves to the active node during failover.
