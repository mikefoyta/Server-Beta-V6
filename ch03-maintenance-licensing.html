Server Maintenance & Licensing Tactical Decoder

High-yield exam-trap switchboard and 5-question scenario drill covering enterprise licensing math, open-source obligations, drive latency tiers, and firmware non-volatile memory.

How True-Up Works

Under an Enterprise Agreement (EA), an organization is authorized to deploy additional software instances, VMs, or seats throughout the year without stopping to issue purchase orders first. Once per year (anniversary date), IT performs an internal count and pays the vendor for the net-new licenses added.

True-Up vs. Vendor Audit

A True-Up is a planned, contractual reconciliation built into an EA. A Vendor Audit is an external compliance inspection where you must produce written or digital proof of entitlement for every active installation or face penalty fees.

SK0-006 Exam Trigger If a scenario describes a fast-growing company spinning up extra servers mid-year and asks which mechanism keeps them compliant by reconciling and paying for the overage at the end of the annual cycle, select True-Up.

Copyleft (e.g., GNU GPL)

  • "Share and share alike" viral obligation.
  • If you modify GPL code and distribute the resulting binary/application, you must release your modified source code under the exact same GPL license.
  • Cannot be wrapped into a closed-source proprietary product.

Permissive (e.g., MIT, Apache 2.0, BSD)

  • Minimal restrictions on reuse and redistribution.
  • You may modify the code, integrate it into a commercial product, and distribute it as closed-source proprietary software.
  • Typically only requires preserving the original copyright notice and license text.
SK0-006 Exam Trigger A software team wants to fork an open-source utility, add proprietary features, and sell it commercially without publishing their source code. They must avoid Copyleft (GPL) and choose a Permissive license.

Per-Socket vs. Per-Core

  • Per-Socket: Counts physical CPU packages plugged into motherboard sockets (e.g., a dual-socket 2U host needs 2 socket licenses regardless of core count).
  • Per-Core: Counts every physical core across all sockets (modern Windows Server requires licensing all physical cores, with a 16-core server minimum).

Physical vs. Virtual OSEs

  • Windows Server Standard: Licensing all physical cores entitles you to 2 Virtual OSEs (VMs) + 1 physical host (for Hyper-V management only). Need 4 VMs? You must stack (buy a second full set of core licenses).
  • Windows Server Datacenter: Licensing all physical cores once grants unlimited virtual OSEs on that host.
SK0-006 Exam Trigger Running 4 Windows Server Standard VMs on a single dual-socket physical host requires licensing the physical host's cores twice (2 OSEs per license set). Above ~10–12 VMs, Datacenter becomes cheaper than stacking Standard.

User & Server Models

  • Per-Concurrent User: Caps simultaneous active sessions. You can install the app on 200 workstations with 100 licenses; user #101 trying to connect at the same moment is denied.
  • Per-Seat (Named User): Every individual user or client device that can access the server requires its own dedicated Client Access License (CAL).
  • Per-Server: Licenses are assigned to the server itself to cover a fixed max number of simultaneous client connections.

Node-Locked & Per-Instance

  • Node-Locked: Strictly tied to a single physical machine's unique hardware identifier (MAC address, CPU ID, or motherboard serial). Replacing the NIC/motherboard breaks activation until re-hosted.
  • Per-Instance: Counts every running OS or container instance, even if multiple instances run on the same physical or virtual host.
SK0-006 Exam Trigger A call center has 300 staff working across three 8-hour shifts (100 staff per shift). Which model minimizes cost legally? Per-Concurrent User (100 licenses).

Forward-Compatible License

Purchased for an older release (e.g., Windows Server 2012) but legally valid to demonstrate compliance for a minor newer release (e.g., Windows Server 2012 R2). Does not cover major version jumps (e.g., 2019 to 2022) unless covered by active Software Assurance.

Site-Based & Volume Licensing

Allows installing software across many systems using a single Volume License Key (VLK) up to a contracted installation ceiling (or unlimited within a specific campus/site boundary), eliminating individual retail product keys.

SK0-006 Exam Trigger Watch the wording: Forward-compatible applies to minor point/R2 releases without buying new keys; mass-deploying 80 identical servers with one key is Volume / Site-Based licensing.

Common Hot-Swappable Components

  • RAID-backed SAS/SATA/NVMe drive sleds
  • Redundant power supply units (PSUs)
  • Redundant chassis cooling fans
  • High-end PCIe expansion cards & hot-add CPU/RAM modules (enterprise mainframes/blades)

Mandatory Pre-Removal Rules

  • Stop active application I/O to the target volume and remove logical software links/mounts first.
  • Verify RAID array redundancy (e.g., RAID 1, 5, 6, 10) before pulling a failed member disk.
  • Never hot-pull a single, unmirrored drive hosting the active OS boot partition.
SK0-006 Exam Trigger "Hot-swappable" means you don't have to power down the server—it does not mean you can yank a drive without first quiescing I/O or unmounting logical links in the OS/RAID controller.

EEPROM (Flash ROM)

Stores the core BIOS or UEFI firmware instructions themselves. Non-volatile without a battery; only rewritten during an intentional firmware flash/update.

NVRAM (CMOS Memory)

Stores variable user/admin configuration settings: boot sequence, system date/time, virtualization flags (VT-x/AMD-V), and port toggles. Sustained by the coin-cell CMOS battery.

SK0-006 Exam Trigger If a server loses its custom boot order and resets its system clock to 1970/2000 on every cold boot, the CMOS battery backing NVRAM has failed—not the EEPROM chip.
