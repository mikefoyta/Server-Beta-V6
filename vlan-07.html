Backup, Recovery & Disaster Recovery (DR)

Full/Incremental/Differential/Synthetic backups, archive bit mechanics, 3-2-1-1-0 rule, RPO/RTO, and Cold/Warm/Hot DR sites.

DOMAIN SCOPE (VLAN 07): Everything inside this room belongs strictly to Data Backup Types, Archive Bit Mechanics, Retention Schemes, Recovery Metrics (RPO/RTO), and Disaster Recovery (DR) Sites.
Backup Type What Gets Backed Up Archive Bit Behavior Backup Speed & Storage Restore Complexity
Full Backup Every selected file/block regardless of modification state Clears archive bit on all files Slowest backup; highest storage usage Fastest restore (Needs only 1 backup set)
Incremental Backup Only data changed since the last backup of any type (Full or Incremental) Clears archive bit after backup Fastest backup; lowest daily storage usage Slowest restore (Requires Last Full + EVERY subsequent Incremental in chain)
Differential Backup All data changed since the last Full backup Does NOT clear archive bit Moderate speed; grows larger each day until next Full Moderate restore (Requires Last Full + ONLY the latest Differential)
Synthetic Full Backup server merges previous Full + Incrementals into a new Full image locally Managed by backup catalog Zero extra network load on production server Fast 1-set restore like a traditional Full backup

Retention Rules & Immutability

  • 3-2-1-1-0 Backup Rule: 3 total copies of data, on 2 different storage media types, with 1 copy stored offsite, 1 copy offline/air-gapped or immutable, and 0 unverified recovery errors.
  • Immutable Backups (WORM): Write-Once-Read-Many storage locks (Object Lock) prevent ransomware or compromised admins from deleting or encrypting backup files before expiration.
  • GFS (Grandfather-Father-Son) Rotation: Tiered retention schedule combining daily Incrementals (Son), weekly Fulls/Differentials (Father), and monthly/annual archives (Grandfather).
  • Bare-Metal Recovery (BMR): Restores an entire OS, system state, applications, and data onto blank replacement hardware without manually reinstalling the OS first.

Recovery Metrics (RPO, RTO, MTTR, MTBF)

  • RPO (Recovery Point Objective): Maximum tolerable amount of data loss measured in time (e.g., an RPO of 1 hour means backups/replication must occur at least hourly).
  • RTO (Recovery Time Objective): Maximum tolerable downtime duration to restore business operations after a failure occurs.
  • MTTR (Mean Time To Repair): Average time required to diagnose, repair, and return a failed component or server to service.
  • MTBF (Mean Time Between Failures): Predicted average elapsed time between inherent hardware failures during normal operation.
