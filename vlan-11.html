Virtualization, Hypervisors & Containers

Type 1 vs. Type 2 hypervisors, vSwitches, Thin vs. Thick provisioning, VM snapshots, Ballooning, Live Migration, and Containers/K8s.

DOMAIN SCOPE (VLAN 11): Everything inside this room belongs strictly to Type 1 & Type 2 Hypervisors, Virtual Networking (vSwitches), VM Storage & Snapshots, Resource Overcommitment, Live Migration, and Containers/Kubernetes.
Architecture Execution Layer Examples Isolation & Footprint
Type 1 Hypervisor
(Bare-Metal)		 Installs directly onto physical server hardware with no underlying host OS VMware ESXi, Microsoft Hyper-V, KVM, Citrix Hypervisor (XenServer) Hardware-level isolation; lowest overhead; enterprise production standard.
Type 2 Hypervisor
(Hosted)		 Runs as a software application on top of a conventional host OS VMware Workstation, Oracle VirtualBox, Parallels Desktop Higher latency due to host OS scheduling; used for dev/test labs only.
Containers
(OS-Level Virtualization)		 Shares the host OS kernel; isolates user-space processes via namespaces & cgroups Docker, containerd, Podman, orchestrated by Kubernetes (K8s) Megabytes in size, millisecond startup; ephemeral by default unless mapped to Persistent Volumes.

VM Storage Provisioning & Snapshots

  • Thick Provisioning (Lazy vs. Eager Zeroed): Allocates 100% of virtual disk capacity upfront (e.g., 500 GB VMDK/VHDX consumes 500 GB immediately); Eager Zeroed wipes blocks upfront for highest initial write speed.
  • Thin Provisioning: Allocates physical blocks dynamically only as data is written; saves storage space but requires capacity alerts to prevent datastore exhaustion.
  • VM Snapshots (Delta Disks): Captures a point-in-time state by freezing the base virtual disk as read-only and writing all new changes to a child delta file (-delta.vmdk / .avhdx).
  • Snapshot Warning: Snapshots are NOT backups; leaving long snapshot chains active degrades I/O performance and risks filling the datastore until consolidated/deleted.
  • Golden Templates & Cloning: Pre-hardened, patched master VM images used to rapidly stamp out identical VMs (requires Sysprep on Windows or cloud-init on Linux to reset SIDs/machine-IDs).

Resource Overcommitment, vSwitch & Migrations

  • CPU & Memory Overcommitment: Assigning more total vCPUs or vRAM across VMs than physically installed on the host.
  • Memory Ballooning & TPS: Balloon driver inside the guest OS reclaims idle RAM from low-priority VMs to give to busy VMs; Transparent Page Sharing (TPS) deduplicates identical memory pages.
  • Virtual Switch (vSwitch): Software Layer 2 switch inside the hypervisor connecting VM vNICs (Port Groups) to physical uplinks (vmnic) and dedicated VMkernel ports (Management, vMotion, Storage).
  • Live Migration (vMotion / Hyper-V Live Migration): Transfers active memory state of a running VM between physical hosts over a dedicated high-speed network with zero user downtime.
  • Storage Migration (Storage vMotion): Moves a running VM's virtual disk files between datastores without powering off the VM.
