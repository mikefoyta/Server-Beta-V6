DOMAIN SCOPE (VLAN 13): Everything inside this room belongs strictly to the CompTIA 7-Step Troubleshooting Methodology, Pre-Boot POST/LED Diagnostics, Hardware Failure Symptoms, OS Boot Recovery, and Live Resource Bottlenecks.

CompTIA 7-Step Troubleshooting Methodology (Exact Exam Order)

  • Step 1: Identify the problem (gather info, check logs, ask what changed, replicate).
  • Step 2: Establish a theory of probable cause (question the obvious; consider top-to-bottom or bottom-to-top OSI).
  • Step 3: Test the theory to determine the cause (if disproven, establish a new theory or escalate).
  • Step 4: Establish a plan of action to resolve the problem and implement the solution (check change control/backups).
  • Step 5: Verify full system functionality and, if applicable, implement preventive measures.
  • Step 6: Document findings, actions, and outcomes in the knowledge base / ticketing system.
  • Golden Rule: Always back up critical data before making destructive changes, and test ONE variable at a time.

Pre-Boot POST, Thermal & Memory Faults

  • POST Beep Codes & Front-Panel LCD/LEDs: Amber/blinking chassis LEDs, front LCD hex codes, or audible POST beep sequences pinpoint failed RAM DIMMs, unseated PCIe cards, or missing CPUs before video initializes.
  • Thermal Shutdowns & Throttling: Caused by dried thermal paste, failed hot-swap fan modules, missing airflow shrouds, or clogged dust filters; check BMC thermal event logs.
  • ECC Memory Errors: Correctable single-bit errors generate BMC warnings; uncorrectable multi-bit errors trigger an immediate Windows BSOD or Linux Kernel Panic / Machine Check Exception (MCE).
  • Swollen / Leaking Capacitors & Burning Smell: Physical board/PSU failure requiring immediate power disconnect and hardware replacement.

OS Boot Failures & File System Repair

  • Windows Boot Recovery: Boot into Windows Recovery Environment (WinRE) and repair corrupted boot records/BCD using bootrec /fixmbr, bootrec /fixboot, and bootrec /rebuildbcd.
  • Linux GRUB2 Recovery: Boot from Live ISO/Rescue mode, mount root/boot partitions, chroot into the system, and run grub2-install + grub2-mkconfig.
  • File System Corruption Checks: Run chkdsk /f /r on Windows NTFS volumes or unmount and run fsck -y /dev/sdX (or xfs_repair) on Linux volumes after unclean shutdowns.
  • Kernel / Driver Rollback: Use Windows Safe Mode / Last Known Good Configuration or select the previous working kernel from the Linux GRUB boot menu after a bad patch/driver update.
