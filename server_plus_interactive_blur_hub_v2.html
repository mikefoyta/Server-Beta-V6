1. The Strict 6-Step Linux Storage Provisioning Chain MANDATORY SEQUENCE

Step 1: Spot Raw Disk (lsblk)
$ lsblk

Locate the new blank disk (/dev/sdb) without touching the live OS drive (/dev/sda).

Verify: Confirm sdb shows type "disk" with no partitions.
Step 2: Fence Partition (fdisk)
$ fdisk /dev/sdb

Carve /dev/sdb1. Press n (new), p (view), and w (write to disk; q quits without saving).

Verify: Run lsblk and confirm sdb1 appears.
Step 3: Format Filesystem (mkfs)
$ mkfs.ext4 /dev/sdb1

Write superblock/inodes and stamp a permanent 128-bit UUID. Unformatted partitions cannot mount.

Verify: Run lsblk -f to confirm FSTYPE & UUID.
Step 4: Create Folder (mkdir)
$ mkdir -p /mnt/mydrive

Create the empty target directory. Linux has no C: or D: drive letters.

Verify: Run ls -ld /mnt/mydrive.
Step 5: Session Mount (mount)
$ mount /dev/sdb1 /mnt/mydrive

Attach the partition for the current runtime session only (vanishes on reboot).

Verify: Run df -h and confirm /dev/sdb1 is listed.
Step 6: Boot Persistence (/etc/fstab)
$ sudo mount -a

Add the 6-column UUID=... entry to /etc/fstab and verify syntax with mount -a before rebooting.

Verify: mount -a exits cleanly with zero errors.

2. Mental Anchors & Single-Letter CLI Flags CLI REFERENCE

Command & Flag Mental Anchor Operational Behavior & Exam Rules
fdisk Fixed Disk ("Fence the disk") Creates/deletes partition boundaries (/dev/sdb1). Never formats or repairs.
mkfs Make Filesystem Formats a partition (mkfs.ext4, mkfs.xfs) and generates a 128-bit UUID. Use -f (XFS) or -F (ext4) to overwrite an existing filesystem.
fsck File System Check Repairs logical metadata corruption after a crash. Always umount first!
badblocks Physical surface scan Scans disk platters/flash for physically dead sectors (badblocks -v /dev/sdb). Never run destructive write-test -w on live data.
df -h / -i / -T Disk Free Shows mounted filesystems only: -h human-readable, -i inode usage (100% inodes = disk full even with free GBs), -T filesystem type.
lsblk -f List Block devices Lists all disks/partitions (mounted or not), plus FSTYPE, LABEL, and UUID.
mount -a / -t / -o Attach storage -a tests/mounts all /etc/fstab entries; -t specifies type; -o passes options (ro, remount,rw, noexec, nosuid).
umount Unmount (no "n" after u) Detaches a mounted filesystem. Returns target is busy if a shell or process has an open file inside.

3. XFS Rules & The 6 Columns of /etc/fstab STORAGE & BOOT MOUNTS

XFS Golden Rules: Default on RHEL/Rocky. Can grow online while mounted (xfs_growfs /mountpoint), but CANNOT shrink (must back up, recreate smaller partition, mkfs.xfs, and restore). Repair unmounted XFS with xfs_repair, not generic fsck.

Sample /etc/fstab Entry: UUID=8f4e2c19-7b3a-4d91-9e02-5c81a4f06b12 /mnt/mydrive ext4 defaults,nofail 0 2

1. Device
UUID=8f4e2c19-...
128-bit UUID from lsblk -f (survives drive letter shifts).
2. Mount Point
/mnt/mydrive
Target directory in the tree.
3. Type
ext4
Filesystem driver (ext4, xfs, vfat, swap).
4. Options
defaults,nofail
nofail stops slow/missing external drives from halting OS boot.
5. Dump
0
Legacy dump backup flag (usually 0).
6. fsck Pass
2
0 = skip, 1 = root / first, 2 = secondary drives.

4. GRUB vs. /etc/fstab, Core Folders & Windows Twins OS ARCHITECTURE

Boot Stage 1 vs. Boot Stage 2

  • GRUB (Stage 1 Bootloader): Runs right after BIOS/UEFI POST to load the Linux kernel into RAM. Edit /etc/default/grub, then run update-grub (Debian/Ubuntu) or grub2-mkconfig (RHEL).
  • /etc/fstab (Stage 2 Mounts): Read by systemd after the kernel starts to mount partitions on boot.

Core Linux Directories & Windows Twins

  • /bin & /sbin = Compiled binaries & admin tools; /etc = Editable Text Configs; /dev = Devices; /var = Variable logs; /opt = Optional third-party apps.
  • Windows Twins: tracert = traceroute | ipconfig = ip a | chkdsk = fsck | diskpart = fdisk | netstat -ano = ss -tulnp.

5. 1+1 PSU vs. Network Redundancy & SK1-006 AI Domain HARDWARE & AI

Power & Network Redundancy Math

  • Golden Rule: True redundancy means normal load never exceeds what remains after a component fails.
  • 1+1 PSUs (e.g., two 1200W): Even when sharing load 50/50, max safe load is 1,200W. If load hits 1,450W and one PSU fails (or bursts exceed single-PSU capacity), the server trips/resets. (2+0 combines wattage with zero redundancy.)
  • Network Equivalent: Active/Passive NIC teaming = 1 link capacity; Active/Active LACP = must keep total traffic under 1 link's ceiling to survive switch failover.

SK1-006 AI Server Infrastructure & Security

  • Power & Thermal: High-density GPU/TPU/NPU racks (30–40+ kW) require upgraded PDUs/UPS, hot/cold aisle containment, and direct-to-chip liquid cooling or rear-door heat exchangers.
  • Privacy & Governance: Sanitize PII/API keys before public AI prompts; host private on-prem LLMs in isolated VLANs for HIPAA/GDPR/classified workloads.
  • AI Threats & AIOps: Guard against indirect prompt injection, RAG data poisoning, model extraction (API rate limiting), RAG RBAC leaks, and enforce human-in-the-loop approval for automated AIOps actions.
